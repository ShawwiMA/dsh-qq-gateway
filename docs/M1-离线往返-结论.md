## 假宿主"忠实"在哪些硬点上（不是宽松假接口）

- `sessionController` 用 Proxy 包住：插件调任何没实现的方法**当场抛错**，不会静默通过。
- `prompt(request, signal)`：少传 `signal` 就抛真机那句 `TypeError: Cannot read properties of undefined (reading 'throwIfAborted')`；`requestId` 必须非空字符串、`mode` 只能是 queue/steer、每个 `content` 段形状都校验、`sessionId` 不匹配抛 `session/not-found`。
- 同一个 `requestId` 重复投递幂等返回 `{accepted:true}` 且不再产生新 turn（照抄 `dsh-agent-loop:855`）。
- 每个 turn 逐条回放 M0 抓到的序列：4 条策略事件 + `agent/inbox/spliced`×2 + `turn/start` + `step/start` + `system/message` + **5 条 `user/message`（1 条带我注入的 rpcId，4 条是 `agent-instructions`/`runtime-context`/`skill-catalog`/`time-context` 且无 rpcId）** + `request/header` + `request/context` + 标题/落库事件 + `assistant/message`（reasoning + text 两块）+ `step/end` + `turn/end`。

## 断言覆盖（22 条，分四类）

- **契约/门控（单元）**：L1/L2 六种帧分类正确；去重；`RidGate` 一次性消费 + TTL 过期 + 上限；`TurnTracker` 四种归属（自己的 / 别人的 rid / 只有 4 条注入 / 一 turn 两 rid 判歧义）；正文只取 text 块。
- **端到端**：QQ 私聊帧 → 收帧到投递 6ms → prompt 形状正确（requestId/mode/content/sessionId/signal）→ 假宿主回放 → 网关发出 `send_private_msg`，文本 = assistant 的 text 块，`user_id` = 主号，reasoning 没漏出去，一 turn 只回一条。
- **红线（L3）**：GUI 发起的 turn（别人的 rpcId）零回传；宿主自己续跑的 turn（一条 rpcId 都没有）零回传；中断（`turn/end=aborted`）的 own turn 零回传；**4 条无 rpcId 注入事件单独回归（M0 坑点 2）**。
- **背压/安全**：错 token 与无 token 握手都被 401 拒；非阻塞（turn 在跑时后续帧照样秒收，echo 帧当场丢）；单飞串行（B 等 A 结束 644ms 才投递，顺序不乱）；`status()` 计数自洽。

**变异测试**：把 `TurnTracker.verdict` 改成永远返回 OWN 后，GUI turn 立刻漏回 1 条、宿主续跑 turn 漏回 2 条——说明那几条"零回传"断言真的能抓到破坏，不是空跑。

## 本轮踩到的两个坑（真机字段，坑 1 是硬伤）

1. **`user/message` 的 `data` 里根本没有 `turn` 字段**（`SessionEventMap['user/message'] = UserMessage`，`turn` 只在 `assistant/message`/`turn/end` 里）。
   第一版按 `data.turn ?? 'current'` 给事件分桶，结果 5 条 `user/message` 全落进另一个桶，`turn/end` 结算的那个 tracker 里一条 rid 都没有 → own turn 被判成外来，22 条断言第一轮挂了 8 条。
   修法：`user/message` 挂到"最近一次 `turn/start`"开的 tracker 上；`turn/end` 结算时再以 rid 为准兜底（谁带着在飞 rid，谁就是这一轮）。
2. **纯图片消息不能被当成有正文**：最初给非文本段留了 `[image]` 占位，等于把"只有一张图"也投进宿主。改成只取 `text` 段，取完是空串就按 `empty-text` 丢掉。

## 已知未覆盖（明确留给后面）

- **超时**：代码里有（`turnTimeoutMs`，超时只记计数、不推 QQ），但 M1 没写断言，留给 M2。
- **断线重连、队列溢出丢最旧、token 轮换**：M2。
- **Config Schema、只读 `/status` 端点**：M3。
- **纯图片/语音消息**目前直接被丢，没有任何回执；要不要回一句"暂不支持"由用户定，M2 再说。
- **入站只支持文本**：OneBot `message` 为字符串（`post_format: 'string'`）时也能吃，但会在 `msg.warnings` 里标 `message-post-format-string`——NapCat 应配 `messagePostFormat: "array"`。
