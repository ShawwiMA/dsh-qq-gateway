# M0 契约探针 —— 结论（2026-10-16）

## 结论：契约成立，红线地基可用

插件调用 `ctx.sessionController.prompt({ requestId, ... }, signal)` 投递的消息，
宿主会把它记成 `user/message` 事件，并且 `event.data.source.rpcId === requestId`。

真机证据（`m0-evidence.log:32`，宿主 pid 34900 = 桌面端主进程）：

```
15:19:40.611  user/message observed rpcId=m0-probe-1792163980467 equal=true
```

对应 `m0-evidence.json`：

```json
{ "verdict": "pass",
  "create":  { "sessionId": "session-9e075742-...", "agentPreset": "ptc" },
  "prompt":  { "accepted": true },
  "match":   { "requestId": "m0-probe-1792163980467",
               "observedRpcId": "m0-probe-1792163980467",
               "equal": true, "sourceKind": "user",
               "sourceKeys": ["kind", "rpcId"], "seq": 9 },
  "rename":  { "title": "[M0契约探针] 可直接删除", "seq": 24 } }
```

时延：apply(0ms) → create(84ms) → prompt(93ms) → user/message 事件(约 +50ms)。

## 三条真机坑点（M1 的假宿主必须照抄）

1. **`prompt(request)` 第二个参数 `AbortSignal` 是必填的。**
   类型声明看不出来，宿主实现里直接调 `signal.throwIfAborted()`，少传一个参数就是
   `TypeError: Cannot read properties of undefined (reading 'throwIfAborted')`。

2. **一轮 turn 里 `user/message` 不止一条，只有自己投的那条带 `rpcId`。**
   实测一次 prompt 产生 5 条 `user/message`（seq 9-13）：

   | seq | source.kind | rpcId |
   |-----|-------------|-------|
   | 9   | `user` | **`m0-probe-…`（自己投的）** |
   | 10  | `agent-instructions` | null |
   | 11  | `runtime-context` | null |
   | 12  | `skill-catalog` | null |
   | 13  | `time-context` | null |

   所以判「这条是不是我投的」只能看 `source.rpcId`，不能看事件类型；
   结论也不能被后面那几条覆盖（第一版探针就栽在这里，误报 mismatch）。

3. **插件模块按包名缓存，改代码后重新 insert 同一包名不会重新求值。**
   实测：`id` 换成新的、`package.json` 的 `main` 换路径都没用，仍然跑旧代码；
   只有换一个没被 import 过的**路径**（`dsh-qq-gateway/lib/rev3/index.js`）才会
   重新 import。运行时不能靠改文件热更插件，M4 真机验收要走重启。

## 附带确认的两件事

- **监听范围**：插件在 profile 根 scope 上 `ctx.on('session/event')` 能看到**别的会话**
  的事件（本轮实测 foreign.sessions=1、events=2，来自用户正在用的那个会话）。
  网关不需要 `follow()` 也能观察目标会话。
- **prompt 幂等**：同 requestId 重复投递在宿主侧是幂等的（源码 `:855`），去重可以少写一层。

## 副作用（如实记录，2026-10-16 23:25 已清理）

探针每跑一次就新建一个会话，共 6 个，标题统一改成「[M0契约探针] 可直接删除」。
实测这 6 个**不全是空壳**：

- 3 个是空壳：只有会话头 + 4 条策略事件 + 标题事件，共 6 个事件，545–550 字节
  （`5536d58b`、`af48da4b`、`b7686f47`）；
- 3 个跑完了整个 turn：26 个事件、约 33KB，含 system prompt、我注入的 prompt、
  模型回复；其中 2 个 `turn/end` 是 `completed`，1 个被探针收尾的 `cancel`
  打断为 `aborted`（`9e075742`、`e1657925`、`a7fe6477`）。
  这 3 个同样会走 `session-log-deepseek`（用户配置里 enabled: true）。

6 个已全部删除，删除前整目录备份到
`~/.dsh/backups/sessions-M0-probe-6-artifacts-20261016/`；
要还原就把里面的 `session-*` 目录整个拷回
`~/.dsh/sessions/--C-Users-you-.dsh-profiles-desktop--/`。

**方法坑（下次别再踩）**：会话文件是 zstd **分帧追加**的，直接
`zstdDecompressSync(整文件)` 只解得出第一帧，会把这 6 个里的 3 个误判成"216 字节空文件"。
必须按 magic `28 B5 2F FD` 切开逐帧解。
