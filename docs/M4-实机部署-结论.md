## 3. 从真机拿到的关键事实

1. **会话 id 带前缀**：磁盘上 header 的 `id` 是 `session-xxxx-...`，不是裸 UUID；配错就是 `session/not-found`，消息静默失效（`accepted=1` 但 `promptsAccepted=0`）。
2. **多帧 zstd**：会话日志是多帧压缩，整文件一次解压只出第一帧；逐帧（按 magic `28 B5 2F FD` 切）才拿到完整事件——排查时别被"只有一行"骗了。
3. **Docker Desktop 是可用性天花板**：本轮它两次自行退出，退出期间网关 `peers=0`、消息进不来。容器 `restart unless-stopped` 只在引擎起来后生效。
4. **容器重启 ≠ 掉登录**：数据卷保住 + `ACCOUNT` 环境变量，重启自动快速登录，10 秒内重连，无需扫码。
5. **Windows 防火墙**：`netsh advfirewall` 里没有 8792 放行规则，也就是没有主动开口子；`0.0.0.0` 监听只对 Docker 网桥有意义。

## 4. 真机阶段修掉的 3 个 bug

| id | 现象 | 根因 | 修法 | 回归 |
|---|---|---|---|---|
| D1 | `prompt failed: session "..." not found` | `sessionId` 少 `session-` 前缀 | patch 改 `session-xxxx-...`，live 重载生效 | 实机重发即通 |
| D2 | `peers` 只增不减（2→3） | HTTP upgrade 的 socket 半开：对端 FIN 只触发 `end`，`close` 永不到来 | `ws.js` 加 `'end'` 处理器 + `setKeepAlive` | `m2-run` 新增三连骤断用例，对旧代码能复现失败 |
| D3 | 热重载后状态端点 `EADDRINUSE` | 旧实例端口未释放，新实例立即 listen | 起端点重试 3 次（700ms 间隔）；`stop()` 先关状态端点再关 WS | `m3-run` 端口冲突用例 |

同时补了**文件日志** `m4-gateway.log`（桌面端 logger 不落盘，这是唯一现场证据来源），以及状态里的 `lastPromptError` 快照——D1 就是靠它定位的。

## 4.1 M4.1 补做：图片消息进会话（2026-10-17）

原 M4 把图片当"不支持的媒体"只回执，主号发图进不了会话。补做后图片可以真正进 DSH：

- 协议层：`protocol.js` 新增 `extractImageSegments`，`parseInbound` 放行图片帧（`msg.images`），图片不再算不支持的媒体。
- 下载层：新增 `lib/gateway/media.js`，按 `url → base64:// → http file → get_image 动作` 四级兜底拿字节，嗅 magic 判 png/jpeg/gif/webp，单图上限 20MB（与宿主 attachment-local 一致）。
- 投递层：`gateway.js` 把图片转成宿主 `PromptContentPart{type:'image', mediaType, data(base64), name}`，文本+图片按顺序一起投。
- 失败兜底（都不静默）：图片全失败且无正文 → 回主号「图片没能接收（下载失败），重发一次或改发文字吧」；有正文就投正文；模型不支持图片 → 回「当前会话的模型不支持图片输入…」。
- 新增动作请求/响应通道 `requestAction`：为 `get_image` 兜底服务，按 echo 认领响应，不影响 L3 判定。
- 新增计数：`imageParts` / `imageFailures`（状态端点可看）。

验收：

- 离线 `test/m4-image.mjs` 9/9：图片段解析、url 下载、文本+图片、`get_image` 兜底、下载失败回执、有正文降级、语音仍回执。
- 离线回归：M1 22/22、M2 27/27、M2 变异 4/4、M3 14/14。
- 实机：探针本地图床 1×1 PNG 通过；真实 QQ 图片（140,161B JPEG，腾讯 CDN url）一次下载成功、进会话、模型正常描述图片内容并回传（日志 `image resolved (url, 140161B, image/jpeg)` → `relayed turn 11`）。
- 证据：`m4-image-evidence.json`。改动：`lib/gateway/protocol.js`、`lib/gateway/media.js`（新）、`lib/gateway/gateway.js`、`test/fake-napcat.mjs`、`test/m1-run.mjs`、`test/m2-run.mjs`、`test/m4-image.mjs`（新）、`test/m4-probe.mjs`。

## 4.2 M5 补做：多人消息（2026-10-17）

- **目标**：小号收到不同人的消息时，DSH 能知道「私聊/群聊、谁发的、群号多少」，回复回到正确的人或群（不再一律回主号）。
- **私聊**：主号始终可回；`allowAllPrivate: true` 后全部好友都可回（小号好友列表由主号自己管理，2026-10-17 按用户要求取消限制）。`/allow`、`/deny`、`/list`、`/help`（中文 `/授权` `/取消` `/名单`）保留，名单落盘 `~\.dsh\bundles\dsh-qq-gateway\allow-list.json`；私聊限制开启时才会用到。
- **群聊**：只接 @ 小号 的群消息（`groupRequireMention` 默认 true），回复用 `send_group_msg` 回原群；群里没 @ 的一律丢弃、不回话。
- **来源标注**：每条投给 DSH 的消息首行是 `【QQ私聊】发送者：昵称（QQ xxx）` 或 `【QQ群聊】群 xxx｜发送者：昵称（QQ xxx）｜@了小号`，并注明回复会发回对方。
- **防回环**：小号自己发的消息直接丢（`skippedSelfMessage`），叠加原有 self_id 校验。
- **新增配置**：总字段 22 → 27：本节的 `groupRequireMention` / `adminEnabled` / `allowListPath`（25），加 `allowAllPrivate`（26）、`stopDockerOnExit`（27）。
- **离线验收**：`test/m5-multi.mjs` 16/16；全量回归 m1 22、m2 27、m3 14、m4-image 9、m4-docker 10、m5 16，m1/m2 变异测试全抓。证据 `m5-evidence.json`。
- **真机（2026-10-17 验完）**：主号私聊 `relayed turn 13`；`/list` 回执 14 字、`/allow 20001` 回执并落盘（JSON 无 BOM）；群 1128332744 里主号与群友 @ 小号 均回复到群（turn 14/15/16）；好友 20001 私聊回复发回好友本人（turn 17/18）；反向：群没 @ 的 `skippedNoMention +1`，`/deny` 后好友私聊 `skippedUnauthorized +1` 且零回复。

## 4.3 M5.2 补做：Docker 联动关闭 + 登录看门狗（2026-10-17）

- **问题**：之前只做了「打开 DSH 自动拉起 Docker」，关掉 DSH 后容器和 Docker Desktop 仍在跑。
- **做法**：`stopDockerOnExit: true` 时，网关 `stop()` 用 detached 子进程拉起 `lib/gateway/shutdown-helper.mjs`，助手等 8 秒后查 **DSH 进程 PID**：还活着 = patch 热重载，跳过；PID 没了 = 真退出，执行 `docker stop napcat-gw` + `docker desktop stop`。父进程退出不影响助手跑完，结果追加进 `m4-gateway.log`。
  - 第一版只看 8792 端口，实测被「7 秒内快速重开 DSH」骗过（新实例抢在助手探测前绑了端口 → 误判热重载、Docker 没停），已改成 PID 判定。
  - 容器 `docker stop` 报错但 `docker desktop stop` 成功时按 `stopped` 记（引擎一停容器必然一起停），并把 stderr 写进日志。
- **登录看门狗**：启动后 120s 仍没有 NapCat 连接就在日志里告警（多半是小号没登录、需要扫码）；状态端点新增 `login: {connected, firstPeerAt, waitingSeconds}`，一眼看出是"没连上"还是"连上后掉了"。
- **配置**：新增 `stopDockerOnExit`（默认 false，总字段 26 → 27）。**已按用户决定关闭**（profile 里 `stopDockerOnExit: false`）：每次关 DSH 都停 Docker，重开就要重新登录小号，2026-10-17 17:21 小号因此被腾讯风控踢下线（提示「设备存在外挂」）；改为容器常驻、只保留 `autoStartDocker`（打开 DSH 时拉起）。功能代码保留，随时可开。
- **离线验收**：`test/m4-docker.mjs` 19/19（新增 7 条：PID 热重载跳过、真退出顺序、容器失败但 Desktop 成功兜底、Desktop 停不掉记 partial、端口兜底、detached 参数、网关接线）。全量回归 m1 22、m2 27、m3 14、m4-image 9、m5 17。
- **真机（2026-10-17 验完）**：开联动时关掉 DSH → 助手日志「Docker Desktop 已停止」（容器 stop 命令报错但引擎已随 Desktop 关掉，按新逻辑记 stopped）；重开 DSH → `docker 联动启动：ok（6s）`，容器 Up 后 NapCat 快速登录成功，启动后 15s `onebot peer connected`。热重载场景日志「DSH 进程仍在运行，跳过停止（热重载）」，不会误停。之后因风控把联动关闭，当前 `stopDockerOnExit: false`。

## 6. 没做的（明说）

- **红线真机步骤没跑**：需要在目标会话 GUI 里手打一句，本轮没做，只有 M2 离线用例覆盖。要做的话：GUI 打开「QQ 网关」会话发一句，期望 QQ 零回传、`skippedForeign +1`。
- **局域网外部可达性没从第二台设备实测**：只确认了本机没有 8792 放行规则、容器网桥可通。
- **Docker Desktop 不会自己保证常驻**：打开 DSH 时会自动拉起（已验证 6s），但没有 Windows 开机自启/看门狗；Docker 若中途退出，需重开 DSH 或手动启动。
- **QQ 风控风险**：NapCat 被腾讯判定为「设备存在外挂」，2026-10-17 17:21 小号被强制下线一次，重新扫码后恢复。频率与使用方式有关，暂无彻底规避手段（改用官方协议/换号是另一回事）。
- **端口 8792 未做 IP 白名单**：只有 Bearer token + 主号/small号 L1/L2 门控 + 防火墙默认拦截三层，没有按来源 IP 限制。
- **多人真机已验证**（见 §4.2 真机行）；`allowAllPrivate` 后私聊默认不再查名单。
- **不做热更新（部分改正）**：实测改 profile patch 会触发 loader 重新加载 bundle 代码（两次生效），但这是旁路现象，正式改动仍建议重启 DSH 后复验。
