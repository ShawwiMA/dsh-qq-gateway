# M7 结论：拟人延迟（自动回传不秒发）

日期：2026-10-19 12:4x（用户要求「制作一个非线性延迟发送消息的脚本给网关用」）

## 要解决什么

模型算完就把整段回复甩出去，QQ 那头是「零点几秒回一大段」；秒回、等间隔回都是
风控容易抓的特征。M7 在**自动回传**这一步加一层非线性延迟。

## 用了什么模型（不是固定 sleep）

延迟 = 下限 + 打字时间 + 长尾停顿，两处非线性：

1. 打字时间按字符数 **0.85 次方** 增长（次线性）——回 5 个字和回 500 个字不该差 100 倍；
   字符权重：中文/全角 = 1，ASCII = 0.5（`effectiveLength`）。
2. 速度抖动 0.7~1.3 倍，每次不同，没有固定节奏。
3. 停顿取 `-ln(1-0.99u)`，即**指数分布**（均值 ≈ `replyDelayTailMs`）——大多数很快，偶尔拖很久。

实测分布（默认参数，2000 次采样）：

| 回复长度 | 中位数 | 均值 | 上限 |
| --- | --- | --- | --- |
| 2 字 | 2.56s | 3.22s | 12.00s（封顶） |
| 10 字 | 2.96s | 3.65s | 12.00s |
| 50 字 | 4.17s | 4.85s | 12.00s |
| 200 字 | 8.10s | 8.41s | 12.00s |

## 改了什么

- 新增 `lib/gateway/human-delay.js`：`effectiveLength` / `computeReplyDelayMs` /
  `createReplyTimeline`。纯逻辑，不碰网络和 cordis，rng 可注入。
- `gateway.js`：新增 `withHumanDelay()`，`sendReply` 和 markdown 图片回复都走它；
  发送用 `setTimeout` 推后，`state === 'stopped'` 时不再发。
- `config.js`：新增 5 个字段（默认值见下），并补跨字段校验 `max >= min`。
- `createReplyTimeline` 保证后算出来的回复不会抢到先算出来的前面。
- **工具调用（qq_send / qq_notice / qq_action）不延迟** —— 那是明确指令，该发就发。
- 回归用例（m1/m2/m3/m4-image/m5/m6-4/m6-6/m6-7/m6-full）统一加 `replyDelayMode: 'off'`，
  只验机制不验时延；时延本身由新增的 `test/human-delay-check.mjs`（纯逻辑）和
  `test/human-delay-live.mjs`（假 NapCat 真跑：400ms 固定延迟实测 418~421ms、
  关掉时 15ms、qq_send 13ms 不受影响）覆盖。

## 新配置项（默认即生效，不用改真实配置）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `replyDelayMode` | `human` | `off` = 退回算完立刻发 |
| `replyDelayMinMs` | 800 | 延迟下限 |
| `replyDelayMaxMs` | 12000 | 延迟上限，必须 >= 下限 |
| `replyDelayPerCharMs` | 60 | 每字折算的打字时间 |
| `replyDelayTailMs` | 2500 | 指数分布停顿的均值 |

## 怎么验

```bash
node test/human-delay-check.mjs   # 纯逻辑：范围、次线性、长尾、配置接线
node test/human-delay-live.mjs    # 假宿主机 + 假 NapCat：延迟真的生效、顺序不乱
```

## 注意

- 改的是插件代码，**要重启 DSH 才生效**（网关模块在启动时加载）。
- 延迟只推迟「回复」，不影响入站消息和回合判定；回合在计算回复时就已收尾，
  `relayed` 计数照旧立刻 +1，日志里能看到 `reply delay XXXXms (拟人)`。
- 备份：`gateway.js.bak-20261019-拟人延迟前`、`config.js.bak-20261019-拟人延迟前`。
