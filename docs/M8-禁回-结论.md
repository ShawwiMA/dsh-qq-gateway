# M8 结论：禁回（禁止回复，可热加载）

日期：2026-10-19 21:5x（用户要求「做个可以热加载的禁止回复时长功能，大号或 DSH 里下命令都能准确执行」）

## 要解决什么

小志（20002）每条私聊都会开一个新回合，AI 每回合都要回一句；而网关配置是
`allowAllPrivate: true`（私聊全放行），主号发 `/deny` 会被全放行绕过，等于没有开关。
M8 补一个真正的开关：**按人或全局禁回，带时长，三条入口，改完即时生效。**

## 三条入口（都写同一份状态，效果完全一致）

1. 主号在 QQ 私聊里发指令（网关自己处理，不进 DSH 会话）：
   - `/mute` = 全局禁回默认 30 分钟（主号除外）
   - `/mute 10` = 全局 10 分钟；`/mute 2h`、`/mute 1d`、`/mute 0` 或 `/mute 永久`（直到解除）
   - `/mute 20002` = 只禁这个人；`/mute 20002 10` = 禁 10 分钟
   - `/unmute` = 全部解除；`/unmute 20002` = 只解这个人
   - `/mute list` = 看当前禁回；`/help` 里也列了
2. DSH 里直接下命令：模型工具 `qq_mute`（`action=mute/unmute/list`，`qq` 填号或 all，`minutes` 分钟）
3. 直接改状态文件（人 / 脚本 / bash）：`~/.dsh/storages/qq-gateway-mute.json`，改完 0.5 秒内生效，
   删掉整个文件 = 全部解禁。

## 热加载怎么做的

`lib/gateway/mute.js` 自己用 `fs.watchFile`（默认 500ms）盯状态文件：mtime 变了就重读，
不用重启 DSH。改状态文件跟用 `/mute` 走的是同一份 JSON，所以三条入口不会打架。

## 行为

- 被禁的人发来的**消息**直接丢：不投给 DSH、不占回合、不回任何话；计数 `counters.mutedSkipped`。
- 排队中的消息在出队时再判一次 —— 刚禁完不会漏回一条。
- **主号永远不受影响**（不然没法 `/unmute` 自救）。
- 状态落盘，DSH 重启后禁回还在（到期自动失效）。
- 时长语义：分钟数；`0` = 永久直到解除。

## 注意

- 只拦**消息**，不拦事件通知（好友申请、撤回提醒这类照旧投递）。
- 禁回只对"发消息给网关"的人生效；群聊里被禁的人 @ 小号也不会触发回复。
- 主号发 `/mute` 必须走**主号私聊**；`adminEnabled: false` 时所有指令关闭（含 /mute）。
