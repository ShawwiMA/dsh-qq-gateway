# M9 安全升级结论（2026-10-26）

1.0.0 / 1.0.1 发布后，做了一轮安全审计（自审 + 对照外部评审给出的 10 项要求），本里程碑只做加固，**不改消息收发语义**。版本目标 1.0.2。

## 一、审计确认的主要风险

按严重度从高到低：

1. 事件帧（notice / request / meta_event）绕过全部门控：不经授权名单、@ 检查、去重、禁回，直接进入模型回合。陌生人发好友申请、群成员撤回消息/传群文件都能触发。
2. 帧内 `user_id` / `group_id` 无签名：能连上网关的人可伪造主号身份，执行 `/allow`（持久后门）、`/mute` 等。
3. 入站素材原样进提示词：昵称、群名片、合并转发正文、申请附言都可被外部控制，没有「数据 / 指令」边界。
4. 出站本机文件无限制：`qq_send` 的 image/file 段接受任意本机路径（含相对路径、UNC），模型被说动就能把本机文件发到任意 QQ。
5. 连接鉴权弱：token 可空、可走 URL query、无 Origin 校验、无握手/空闲超时、无帧大小上限、畸形请求行可让宿主进程退出。
6. 多 peer 无绑定：后连上来的连接会接管全部出站动作，回复可被窃听、动作结果可被伪造。
7. 入站无频率限制、无重复内容检测：刷屏能烧 token 并把主号消息挤出队列（旧实现丢最旧）。
8. 状态端点无鉴权；日志含 QQ 号 / 群号。
9. 管理动作只有一个全局开关，不看发起者。

## 二、改动清单

连接层（`lib/gateway/ws.js`）
- 握手：`Origin` 头默认拒绝、token 只认 `Authorization`（`allowQueryToken` 默认关）、sha256 + `timingSafeEqual` 比较。
- 抗崩：整个 upgrade 回调 try/catch，畸形请求行回 400 不再抛成未捕获异常；每个 socket 挂 error 监听。
- 限制：握手 5s、空闲 120s 超时；`maxFrameBytes` / `maxMessageBytes` 超限回 close 1009 断开。
- 单 peer：同时只保留一条 NapCat 连接，多余的直接断开（计数 `extraPeers`）。

配置层（`lib/gateway/config.js`、`lib/index.js`）
- 新增 14 个字段：`allowQueryToken`、`allowOrigin`、`maxFrameBytes`、`maxMessageBytes`、`maskLogQQ`、`rateLimitPerMinute`、`autoMuteMinutes`、`dupWindowMinutes`、`burstMergeMs`、`eventPromptRequests`、`highRiskActionsRequireMain`、`outboxDir`、`fileSendPolicy`、`statusToken`（合计 60 项）。
- 启动组合校验：`token` 必填；监听非环回地址时要求 >= 32 位；状态端点非环回时 `statusToken` >= 32 位；非环回禁止 `allowQueryToken`。不满足拒绝启动，不会带着弱配置裸跑。

入站层（新增 `lib/gateway/guard.js` + `gateway.js` 集成）
- 按来源令牌桶限流（默认 10 条/分钟），主号豁免；连续超限阶梯式自动禁回（`autoMuteMinutes`，0=只丢弃）。
- 内容指纹去重：同一来源同一段文字在 `dupWindowMinutes` 内只投一次（换 message_id 也算）。
- 连发合并：同一来源在 `burstMergeMs` 窗口内的纯文字合并成一个回合（提示词里标注「连发 N 条」）。
- 队列：主号消息插队并保持先后顺序；满时挤掉最旧的非主号消息，非主号新消息直接丢。
- 事件路径复用门控：禁回、限流、去重；好友/加群申请默认不投模型（`eventPromptRequests` 显式打开才投）。
- 提示词增加「外部用户」标注与操作规范技能指引。

出站层（`lib/gateway/actions.js`、`lib/gateway/tools.js`）
- `fileSendPolicy`：`main`（默认）= 只有主号发起的那一轮能发本机文件；`outbox` = 非主号只能发 `outboxDir` 内文件；UNC 路径一律拒绝；base64/file 原始字节段只给主号。网关内部渲染（Markdown 截图）标记为 trusted。
- `highRiskActionsRequireMain`：`qq_action` 的写/破坏性动作只允许主号回合触发；查询类不受限。

日志与状态
- 文件日志默认打码 QQ 号/群号/消息 id（`maskLogQQ`）。
- 状态端点支持 `statusToken`，非环回必须配置。

模型侧
- 新增技能 `qq-gateway-operator`（`~/.dsh/skills/qq-gateway-operator/SKILL.md`）：主客判定、越权拒绝、注入处理、工具用法、合并回复、隐私红线。

测试
- 新增 3 套离线验收 34 条断言：`m9-guard.mjs`（14）、`m9-ws-security.mjs`（7）、`m9-security.mjs`（13）。
- 原有 17 套全部更新到新行为（单 peer、申请默认不投、队列策略），共 20 套。

## 三、对照外部评审 10 项

| 评审项 | 处理 |
| --- | --- |
| 强制校验非空 Token / 防跨域网页连接 | 已做：token 必填 + 非环回 >=32 位；Origin 默认拒绝；query token 默认关 |
| 握手 URL 异常捕获 | 已做：畸形请求行 400，进程不再退出 |
| maxPayload 防 OOM | 已做：单帧 4MB / 单条 16MB 上限，超限 1009 断开 |
| 防命令注入 / 高危指令人工确认 | 部分：写/破坏性动作只认主号回合；出站文件分级。DSH 会话工具权限需在 DSH 侧降权，插件做不到 |
| 防重放 | 部分：单连接绑定、消息/事件去重、token 不落日志。OneBot 11 协议无签名/时间戳，协议层防重放做不到 |
| 敏感信息脱敏 | 已做：日志打码；状态端点可加 token |
| 限流防刷 | 已做：按来源令牌桶 + 阶梯禁回 + 队列优先级 |
| 防 SSRF | 未做（残留）：入站图片下载只允许 http(s)，没有私网 IP 黑名单；列入后续 |
| 连接超时 | 已做：握手 5s / 空闲 120s / 单 peer |
| 依赖审计 | 说明：本项目零运行时依赖（仅可选 peer `@deepseek-ai/dsh-tools`），`cargo audit` 不适用，对应 `npm audit --omit=dev` |

## 四、残余风险（如实记录）

1. 没有群白名单：小号被拉进任意群后，任何成员 @ 一次仍可触发（限流会兜底）。后续加 `groupAllowList`。
2. 提示词注入无法根除。真正的边界是「网关会话里有哪些工具」，建议在 DSH 侧不给该会话 shell / 写盘 / 屏控。
3. 防重放受 OneBot 11 协议限制，只能做到连接绑定 + 去重；生产环境建议只监听环回，前面挂 TLS 反代。
4. `containerProxy` 仍是本机无鉴权 TCP 转发（只监听 127.0.0.1），后续可加目标白名单。
5. 入站图片下载没有私网/回环黑名单（SSRF 面）；正常 NapCat 消息的图片 URL 来自 QQ CDN，风险主要在 token 泄露/伪造帧场景。
6. QQ 账号本身的风控与封禁不在插件控制范围。
